01 / RUNTIME TOPOLOGY

สี่บริการ แยกหน้าที่ชัดเจน

Four services, separate responsibilities. Arrows show requests and access; response paths are omitted here.

เฉพาะ bot มีคีย์และ volume ข้อมูล ส่วน MCP ไม่มีคีย์ Discord/Groq หรือฐานแชท เบราว์เซอร์อยู่ในเครือข่ายภายในและออก HTTPS ผ่าน proxy เท่านั้น
Only the bot holds credentials and the data volume. MCP services have neither chat storage nor bot credentials; the browser has proxy-only HTTPS egress.

02 / APPLICATION RESPONSIBILITIES

ตรวจสิทธิ์ก่อนทำ และก่อนส่ง

Check access before work and before delivery. Source follow-ups bypass generation; emergency controls bypass the AI queue.

เลือกแหล่งค้น / Pick the source

คำถามกำกวมให้เลือกเว็บ ประวัติ หรือทั้งคู่ ปุ่มตอบให้ผู้ถามคนเดียวและหมดอายุ 5 นาที ถ้าเลือกทั้งคู่ต้องตรวจคำค้นสาธารณะก่อน ประวัติในดิสไม่ถูกส่งไปเป็นคำค้นเว็บเองAmbiguous requests offer web, history or both. Owner-bound buttons return private answers and expire after five minutes. Combined lookup confirms a public query separately; history is never automatically exported as a web query.

ที่มาเมื่อขอ / Sources on request

ปกติซ่อนที่มา กดดูที่มาหรือถาม “เอามาจากไหน” เพื่ออ่านแหล่งของคำตอบนั้นและตรวจสิทธิ์ใหม่ โดยไม่เรียก AI อีก ข้อความยาวแบ่งส่งตามขนาด DiscordProvenance is hidden until requested. Source buttons target their own answer, revalidate access and use no extra generation. Long replies split into Discord-sized parts.

03 / DISCORD CONTROL SURFACE

ตั้งค่าได้โดยไม่ต้องมีเว็บแอดมิน / Controls without a web admin

ส่วน / Areaสิ่งที่ทำได้ / Behaviorขอบเขต / Boundary
/panelโทน ความยาว ห้อง เครื่องมือ ข่าว และสถานะTone, length, rooms, tools, news and health.ผู้ใช้แก้ค่าตัวเอง แอดมิน Manage Server แก้ค่าระบบ ตรวจสิทธิ์ใหม่ทุกครั้งPersonal preferences or fresh admin authorization; five-minute controls.
บุคลิก / Conversationโทน 0–4 รวมโหมดเรื้อน ตอบสั้นหรือยาวตามงาน พูด “พอ” เพื่อหยุดแซว 30 นาทีAdaptive length, tone 0–4 and temporary gentle mode.ใช้ระดับต่ำกว่าระหว่างคนกับห้อง การแทรกคุยยังปิดจนเปิดรายห้องPersonal and room caps apply; interjections are opt-in.
/jokeเสนอมุกประจำห้อง เจ้าตัวยินยอมและแอดมินอนุมัติ ลบได้ อายุ 30 วันSubject consent plus admin approval; removable jokes expire after 30 days.ไม่ใช่ข้อเท็จจริงส่วนตัว เก็บได้ 20 มุกต่อห้องOptional references, not verified personal facts; 20 per room.
ค้นต่อ / Follow-upหาเพิ่ม เจาะคำค้น เทียบไม่เกิน 3 ลิงก์ และตั้ง RSS ประจำห้องContinue, refine, compare up to three links and choose a room feed.เว็บตัด URL ซ้ำแบบ best effort ประวัติใช้ cursor ตามสิทธิ์ ไม่ส่งข่าวเองBest-effort public deduplication, scoped history cursors; no automatic news posts.
สิทธิ์และงบ / Policy & budgetเปิดเครื่องมือรายห้อง กำหนดบทบาท และจองโควตาก่อนเรียกRoom/tool role policies and durable pre-call reservations.ค่าปิดมีผลเหนือเปิด ยอดเงินเป็นประมาณการจากราคาที่แอดมินตั้งDeny wins. Monetary estimates require a manually configured price.
/stopหยุดห้องหรือเซิร์ฟเวอร์ ระบายคิวและยกเลิกงานในขอบเขตStop a room or guild, drain matching jobs and cancel active processing.ไม่เล่นงานเก่าซ้ำเมื่อเปิดกลับ งานที่ถึงผู้ให้บริการแล้วอาจมีค่าใช้จ่ายNo replay on resume; already accepted external requests may incur charges.

04 / DATA LIFETIME & RECOVERY

แยกสิ่งที่จำชั่วคราว ออกจากสิ่งที่เก็บถาวร

ในหน่วยความจำ / RAM only

คำถามและคำตอบล่าสุด รวมที่มาเว็บและสถานะค้นต่อ อยู่ในขอบเขตคน/ห้อง/ส่วนตัวและหมดอายุเริ่มต้น 30 นาที ฉากสนทนาสำหรับแทรกคุยใช้เพียง 30 วินาที ไม่เก็บข้อความคำตอบ AI ลงฐานRecent dialogue, public references and follow-up state are scoped by user, channel and privacy mode with a 30-minute default lifetime. Interjection scenes live for 30 seconds. Generated answers are not stored in SQLite.

บน volume / Persistent data

SQLite เก็บประวัติที่อนุญาต ความจำที่ยืนยัน ตั้งค่า มุกที่อนุมัติ โควตาและรหัสที่มา มี backup ตามรอบ บันทึกการลบ privacy-ledger.sqlite3 แยกจาก backup หมุนเวียนและต้องรักษาไว้SQLite holds eligible history, confirmed memories, approved jokes, settings, quotas and source IDs. Keep the separate deletion journal alongside recovery assets; do not replace it with an older copy.

“อย่าจำฉัน” หรือ /privacy ปิดเก็บใหม่และลบข้อมูลที่บอทเก็บ ไม่ลบข้อความต้นฉบับใน Discord การกู้คืนใช้บันทึกการลบปัจจุบันเพื่อกันข้อมูลกลับมา ทดสอบกู้คืนสัปดาห์ละครั้งในพื้นที่ชั่วคราว หรือสั่งจากหน้าสถานะได้ Opt-out erases the bot’s retained personal data, not original Discord messages. Recovery reapplies the current deletion journal. Weekly or manual recovery drills use disposable copies and never replace the live database.

ห้องข้อความที่บอทเห็นและส่งได้เรียกคุยด้วยแท็ก/ตอบกลับได้ ห้องบอทไม่ต้องแท็ก การคุยในห้องใหม่ไม่เปิดเก็บประวัติหรือแชร์ข้ามห้องเอง การแชร์ในห้องยังต้องพิสูจน์ว่าผู้รับทุกคนอ่านต้นทางได้ ส่วน /ask ตรวจสิทธิ์ผู้ถามและบอท Visible/sendable text rooms support mentions and replies; designated bot rooms allow untagged chat. New rooms do not automatically enable history storage or cross-room sharing. Public delivery requires an audience proof; private /ask checks requester and bot access.

สิ่งที่เปิดใช้ / Implemented: เครื่องมืออ่านอย่างเดียว 6 ตัว: DuckDuckGo search, fetch, RSS/Atom, RSS news, YouTube captions และ Playwright DOM reader ไม่มีเครื่องมือจัดการเซิร์ฟเวอร์ดิสSix reviewed read-only tools. The Playwright service is a narrow purpose-built MCP reader, not a general browser automation toolbox.

ขอบเขตการป้องกัน / Limits: อ่านข้อมูลได้แบบจำกัดจำนวน บางเว็บหรือคลิปอ่านไม่ได้ และตัวกรองบุคลิก/ข้อมูลส่วนตัวเป็น heuristic เบราว์เซอร์ใช้ --no-sandbox ร่วมกับ container/network/request isolation ไม่ใช่คำรับรองความปลอดภัยของทุกเว็บBounded retrieval, external availability limits and heuristic classifiers remain. Chromium uses --no-sandbox with container, network and request controls; no universal website safety is claimed.

สถานะตาม snapshot / Evidence: Docker 4 ตัว healthy, 192 unit tests + 2 HTTP tests และทดสอบกู้คืนผ่าน ตรวจคำสั่งจริงและ MCP discovery หลังเปิดใช้แล้วRecorded rollout evidence: four healthy services, 192 unit plus two HTTP tests, recovery smoke and actual command/MCP discovery checks. This document does not run live checks.
