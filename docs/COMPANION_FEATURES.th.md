# คุยต่อเรื่อง เสนอจำ ค้นต่อ และดูแลระบบ

เพิ่มตามคำสั่งเจ้าของเมื่อ 2026-10-27 อ่านผลทดสอบ/เปิดใช้จริงล่าสุดใน [PROGRESS.md](../PROGRESS.md)

## คำตอบตัวเองระยะสั้น

บอทใช้คำถามและคำตอบล่าสุดของตัวเองเพื่อเข้าใจ “อันที่สองล่ะ”, “ต่อดิ”, “ทำไมพูดงั้น” เก็บเฉพาะ RAM สูงสุด 3 รอบต่อคน/ห้อง แยกเซิร์ฟเวอร์และคำตอบส่วนตัวจากห้องปกติ อายุเริ่มต้น 30 นาที จำนวน session รวมไม่เกิน 200 และบริบทที่ส่ง AI ยังมีเพดานขนาดเดิม จึงอาจไม่ได้รวมทุกรอบหรือคำตอบยาวทั้งหมด

ไม่เขียนข้อความคำตอบลง SQLite หรือ backup รีสตาร์ตแล้วหาย การปิดเก็บข้อมูล `/privacy store_data:false`, การล้างความจำ การแก้/ลบแหล่งข้อมูลที่เกี่ยวข้อง หรือการเปลี่ยนสิทธิ์ที่ตรวจพบ จะล้างบริบทชั่วคราวและตำแหน่งค้น บอทตรวจสิทธิ์และต้นทางอีกก่อนส่ง AI/ส่งคำตอบ คนที่ปิดเก็บข้อมูลยังถามได้ แต่ไม่เก็บรอบสนทนาไว้

ลองในห้องบอท:

1. “เสนอเกมเล่นกับเพื่อนมา 2 เกม”
2. “อันที่สองล่ะ อธิบายเพิ่มหน่อย”

## เสนอจำพร้อมยืนยัน

เมื่อเจ้าตัวบอกความชอบหรือชื่อที่อยากให้เรียกอย่างชัดเจน เช่น “ผมชอบเกมแมว” บอทอาจแนบข้อเสนอพร้อมปุ่ม **จำไว้ / ไม่ต้องจำ** หลังตอบ มีเฉพาะเจ้าของข้อมูลในห้องเดิมกดได้ ข้อเสนอหมดอายุใน 5 นาที และตรวจข้อความต้นทาง/สิทธิ์ใหม่ก่อนบันทึก

ไม่มีความจำถาวรเพิ่มก่อนกด “จำไว้” ข้อความที่เป็นคำถาม มุกที่ระบุว่าล้อเล่น คำพูดอ้างจากผู้อื่น ข้อมูลอ่อนไหวหรือรหัสที่ตรวจจับได้จะไม่ถูกเสนออัตโนมัติ รุ่นนี้ใช้กฎเลือกข้อความแบบระมัดระวัง ไม่ได้สรุปทุกข้อความด้วย AI และไม่มี AI call เพิ่มสำหรับการเสนอจำ

- เสนอได้ไม่เกินหนึ่งครั้งต่อคนต่อชั่วโมง ไม่เสนอเรื่องที่จำตรงกันแล้ว
- ปิดข้อเสนอส่วนตัวด้วย `/memory suggestions enabled:false` หรือเปิดด้วย `true`
- ตรวจ/แก้/ลบที่ยืนยันแล้วด้วย `/memory list`, `/memory edit`, `/forget`
- ถ้าข้อความอยู่ในห้องปกติ ข้อเสนออยู่ห้องเดียวกัน หากใช้ `/ask` ข้อเสนอเป็นส่วนตัวเช่นเดียวกับคำตอบ
- สิทธิ์/ข้อมูลเปลี่ยนหรือรีสตาร์ต ปุ่มเดิมอาจใช้ต่อไม่ได้ ใช้ `/remember` ได้เสมอเมื่อมีสิทธิ์และไม่ได้ปิดเก็บข้อมูล

## ค้นต่อโดยไม่วนชุดเดิม

เริ่มด้วยคำถามมีหัวข้อ/ห้อง/ช่วงเวลา เช่น `/ask question:ก่อนบอทเข้า ห้องพิมพ์คุยเคยคุยเรื่องเกมอะไร` แล้วถาม `/ask question:หาเก่ากว่านี้` หรือ `หาเพิ่ม` บอทจำหัวข้อและช่วงเวลาเดิม ใช้รหัสข้อความเป็น cursor แยกแต่ละห้อง ไม่ใช้เพียงเวลา จึงไม่วนข้อความที่มีเวลาใกล้กัน

`เฉพาะเดือนนั้น` ปรับการค้นให้เป็นเดือนปฏิทินของวันเริ่มค้นเดิม หรือเดือนของข้อความท้ายชุดที่เพิ่งตรวจ ถ้ายังไม่มีจุดอ้างอิง บอทให้เริ่มระบุหัวข้อ/เวลาใหม่ การปรับเดือนเริ่มค้นเดือนนั้นใหม่ จากนั้นใช้ “หาเพิ่ม” เพื่อเดินชุดต่อไปได้ การค้นที่เริ่มจากข้อความแรกสุดจะเดินจากเก่าไปใหม่

ตำแหน่งค้นอยู่ใน RAM อายุ 30 นาที แยกคน ห้อง และส่วนตัว/ปกติ ถ้าค้นด้วย `/ask` ให้ใช้ `/ask` ค้นต่อด้วย ตำแหน่งขยับหลังส่งคำตอบสำเร็จ ถ้า AI/โควตาล้มเหลว การลองใหม่ยังใช้ cursor เดิม มีเพดานต่อห้อง/จำนวนห้อง/จำนวนรวม/เวลาเดิม และแจ้งเมื่อไม่พบเพิ่มหรือไม่มี session ไม่มีการรับประกันว่าสแกนครบทั้งเซิร์ฟเวอร์

แหล่งอ้างอิงยังซ่อนจนกว่าจะถาม “เอามาจากไหน” คำตอบยาวยังแบ่งส่งตามเดิม

## สำรองและแจ้งเตือน

เริ่มต้นสำรองทันทีเมื่อบอทพร้อม หากยังไม่มี backup อัตโนมัติที่ถึงเกณฑ์ แล้วทำทุก 24 ชั่วโมง ตรวจความสมบูรณ์ SQLite รวมข้อมูล WAL ก่อนเผยไฟล์ `.sqlite3` ที่เสร็จแล้ว งานสำรองมีงบเวลา 30 วินาทีและไม่บล็อก event loop

เก็บไฟล์ `auto-*.sqlite3` ใน `/app/data/backups` ภายใน volume เดิม อายุ 7 วันและสูงสุด 32 ชุด ลบเฉพาะไฟล์ของตัวสำรองอัตโนมัติหลังสร้างไฟล์ใหม่สำเร็จ ไม่ลบ manual backup และไม่ลบไฟล์ล่าสุด หากล้มเหลวจะเก็บสำเนาเดิมและลองใหม่หลัง 10 นาที ตรวจด้วย `/status`

ไฟล์สำรองอยู่ดิสก์/volume เดียวกับฐานข้อมูล ควรคัดลอกไปอีกที่เพื่อรับมือดิสก์สูญหาย มีประวัติ/ความจำใน backup และการลบข้อมูลปัจจุบันไม่ลบสำเนาย้อนหลังทันที อายุ backup จึงแยกจากการลบข้อมูลหลัก ก่อนกู้ให้หยุดบอทและกู้ลงไฟล์ใหม่ตาม [คู่มือ](OPERATIONS.th.md#9-สำรองและกู้ข้อมูล)

บอทแจ้งปัญหาคีย์/โมเดล, AI 429, งานประมวลผลล้มเหลว, worker หยุด, backup ล้มเหลว และโควตาในเครื่องแตะ 80% ผ่าน DM เจ้าของเซิร์ฟเวอร์เป็นค่าเริ่มต้น ไม่มีคีย์หรือเนื้อหาแชทในแจ้งเตือน เลือกห้องด้วย `/settings alerts enabled:true channel:#ห้องแอดมิน` หรือไม่เลือกห้องเพื่อกลับไป DM ปิดด้วย `enabled:false` ต้องมี Manage Server

ปัญหาชนิดเดียวกันแจ้งซ้ำไม่ถี่กว่า 6 ชั่วโมง บันทึกเวลาไว้ข้ามรีสตาร์ต ถ้าส่งไม่สำเร็จจะแสดงใน `/status` และลองใหม่หลัง 10 นาที ตัวบอทต้องออนไลน์และส่ง Discord ได้ ระบบนี้แจ้งไม่ได้เมื่อทั้งเครื่อง/เครือข่ายหยุด โควตาเป็นตัวนับในเครื่องที่เผื่อสูง ไม่ใช่ยอดคงเหลือจริงจากบัญชี Groq

## ตัวปรับแต่ง `.env`

| ค่า | เริ่มต้น | ความหมาย |
|---|---:|---|
| `CONVERSATION_TTL_SECONDS` | 1800 | อายุความจำคำตอบใน RAM; 0 ปิด |
| `CONVERSATION_TURNS` | 3 | จำนวนรอบสูงสุดต่อ session |
| `MEMORY_SUGGESTIONS` | true | เปิดข้อเสนอจำทั้ง instance |
| `BACKUP_INTERVAL_HOURS` | 24 | รอบ backup; 0 ปิด |
| `BACKUP_RETENTION_DAYS` | 7 | อายุไฟล์อัตโนมัติ มีเพดาน 32 ชุด |
| `QUOTA_ALERT_PERCENT` | 80 | เกณฑ์แจ้งโควตาในเครื่อง |

แก้ `.env` แล้ว `docker compose up -d --force-recreate bot` ข้อมูล SQLite และการตั้งค่าผู้ใช้ยังอยู่ บทสนทนาชั่วคราว/ตำแหน่งค้น/ปุ่มรอยืนยันหายเมื่อรีสตาร์ต ไม่ต้องเปิด GUI หรือพอร์ตเพิ่ม

อ่านรูป/แคปหน้าจอและเสียงในห้อง voice ยังไม่อยู่ในงานชุดนี้
