# คำแก้ความเข้าใจ Feedback สรุปช่วงที่ไม่อยู่ และโควตาจริง

2026-10-28 · ผลเปิดใช้จริงดู PROGRESS.md

## แก้ความเข้าใจผิด

พิมพ์ “หมายถึงทีมฟุตบอล ไม่ใช่อนิเมะ”, “ที่หมายถึงคือ…” หรือ “I meant …” บอทจะใช้คำถามเดิมของคุณร่วมกับคำแก้ล่าสุดในขอบเขตคน/ห้อง/ส่วนตัวเดียวกัน หากตอบกลับคำตอบเก่า จะเลือก turn ที่มีรหัสคำตอบนั้น ไม่แก้จากบทสนทนาของคนอื่นหรือจากห้องอื่น

ใช้ความต่อเนื่อง RAM เดิม (ค่าเริ่มต้น30นาที/3turns) ไม่สร้างความจำถาวรจากคำแก้ เมื่อหมดอายุ ปิดเก็บข้อมูล หรือไม่พบคำตอบที่ระบุ จะขอคำถามเต็ม ไม่เดาต่อจากเรื่องของคนอื่น สิทธิ์ ต้นทางและการแก้/ลบข้อความยังตรวจเหมือนเดิม

เมื่อคำแก้สืบเนื่องจากเรื่องที่ต้องค้นเว็บ เช่นสกอร์ ข่าว ราคา หรือลิงก์ จะแสดงปุ่มให้ตรวจคำค้นสาธารณะ โดยเริ่มช่องว่าง ไม่ส่งคำถาม/บริบทเก่าออกไปค้นอัตโนมัติ ห้องที่ปิดเว็บจะบอกตามจริง

## ประเมินคำตอบ

ท้ายคำตอบที่มีปุ่มควบคุมจะมี **ตอบมั่ว / ยาวไป / ไม่ฮา** ผู้ถามคนเดิมกดได้ใน5นาที ตอบรับแบบส่วนตัวด้วย Discord deferred channel message (ephemeral) ไม่เปลี่ยนข้อความคำตอบในห้อง

เก็บเฉพาะรหัสคำตอบ คน/ห้อง/เซิร์ฟเวอร์ ประเภท เวลา และสถานะคำตอบส่วนตัว ไม่มีการคัดลอกคำถาม คำตอบ หรือข้อความแสดงความคิดเห็นอิสระ หนึ่งคำตอบมีหนึ่งรายการ กดอีกประเภทคือเปลี่ยนรายการเดิม ไม่เพิ่มคะแนนซ้ำ คนปิดเก็บข้อมูลจะไม่ถูกบันทึก feedback

แอดมินใช้ `/feedback` หรือ `/panel` → ข้อเสนอแนะคำตอบ ต้องผ่าน Manage Server และเห็น/อ่านประวัติห้องต้นทางได้ จะแสดงจำนวนแยกประเภทและลิงก์เฉพาะคำตอบสาธารณะ คำตอบส่วนตัวแสดงแค่ประเภท ไม่มีเนื้อหา/ลิงก์คำตอบส่วนตัว ไม่แจ้ง DM แอดมินอัตโนมัติ และไม่เปลี่ยนโทน/ความยาวหรือฝึกโมเดลเองจากการกดครั้งเดียว

รายการเชื่อมกับ `answers` ผ่าน foreign key ลบตามคำตอบ/คำขอลบข้อมูลผู้ใช้ และหมดอายุตามข้อมูลคำตอบ (ค่าเริ่มต้น30วัน) การกู้คืนใช้ privacy ledger ปัจจุบันกันข้อมูลที่ลบแล้วกลับมา

## สรุปช่วงที่ไม่อยู่

ตัวอย่าง:

- “ตั้งแต่เมื่อคืนพลาดอะไรบ้าง” — เริ่ม18:00ของวันก่อนถึงเวลาปัจจุบัน
- “วันนี้พลาดอะไรบ้าง” — เริ่ม00:00วันนี้
- “พลาดอะไรตั้งแต่วันนี้09:30” — ใช้เวลาที่ระบุ
- “สรุปแชทตั้งแต่เดือนที่แล้ว” — เริ่มวันแรกของเดือนก่อน
- `/catchup hours:6` — ย้อนหลัง6ชั่วโมง (คำสั่งรองรับ1–168ชั่วโมง)

ใช้เขตเวลาที่ตั้งไว้ (เริ่มต้นAsia/Bangkok) หากไม่ระบุช่วงเวลา ใช้24ชั่วโมงล่าสุด แสดงวันที่/เวลาเริ่ม–จบและชื่อเขตเวลาชัดเจน วันที่แบบYYYY-MM-DD ใช้ปีค.ศ. เวลาผิด/ช่วงอนาคตที่ระบุชัดเจนต้องแจ้งให้แก้

สรุปแยกหัวข้อ ข้อสรุปที่ตกลงจริง และเรื่องที่ยังค้าง หากไม่มีหลักฐานให้บอกว่าไม่พบ ไม่แต่งผู้รับผิดชอบ เส้นตาย หรือข้อตกลง ไม่เอาความจำส่วนตัว/คำตอบเก่านอกช่วงมาเติม ที่มายังซ่อนจนถาม

เป็น **ตัวอย่างประวัติที่ดึงได้ตามสิทธิ์และขีดจำกัดเดิม** ไม่รับรองว่าอ่านทุกข้อความ ข้ามห้องยังผ่าน audience proof สำหรับคำตอบสาธารณะ หรือสิทธิ์ผู้ถามสำหรับ /ask ห้องใหม่ที่ยังไม่เปิดอ่านจะไม่ถูกเปิดเก็บเอง ปุ่มหาเพิ่มรักษาช่วงเวลาของสรุปเดิมและค้นชุดถัดไปแบบส่วนตัว

## ลดข้อความช่วงพัก และแสดงเฉพาะโควตาจริง

เอาข้อความ “ถึงโควตาหรือช่วงพักแล้ว รอประมาณ…วินาที” ของตัวนับภายในออก ช่วงพักสั้นไม่เกิน25วินาที ลอง AI operation ที่ยังเริ่มไม่ได้อีกหนึ่งครั้ง โดยไม่ทำ MCP/ดึงประวัติซ้ำ ตรวจสิทธิ์ สถานะข้อมูล โทน เครื่องมือ และ privacy ใหม่ก่อนลองต่อ ยังคง deadlineทั้งงาน90วินาที งานแทรกคุยไม่รอเพื่อแย่งคิว

จอง token สำหรับงานที่กำลังทำ เมื่อผู้ให้บริการรายงานการใช้จริง ให้ใช้จำนวนที่รายงานแทนค่าประมาณเดิม การใช้ที่ไม่รายงานยังถือการจองไว้ งบเงินที่แอดมินตั้งยังใช้การจองแบบอนุรักษ์ ข้อจำกัดจริงของผู้ให้บริการไม่ถูกเพิ่มหรือหลบเลี่ยง

หน้าโควตาใน `/panel` และ `/status` รวมถึงแจ้งเตือนโควตา ใช้เฉพาะ headers จากการตอบ Groq ครั้งล่าสุด:

| ค่า | ความหมายตาม Groq |
|---|---|
| `x-ratelimit-*-requests` | จำนวนคำขอต่อวัน (RPD) |
| `x-ratelimit-*-tokens` | tokenต่อนาที (TPM) |
| `x-ratelimit-reset-*` | เวลาถึงการรีเซ็ตที่ API รายงาน |

แสดง limit/remaining ที่รายงาน พร้อมเวลาอัปเดต ค่าที่ไม่ส่งมา เช่นRPM/TPD จะแสดง “ยังไม่มีข้อมูล” ไม่ใช้ตัวนับบอทเดา และไม่ถือข้อมูลเก่าว่าเป็นยอดปัจจุบัน โควตาอาจใช้ร่วมกับแอปอื่นในองค์กร ผู้ให้บริการอื่นที่ไม่มีตัวอ่านเฉพาะจะแสดงไม่ทราบแทนการตีความ headers ผิด

ข้อจำกัดภายในยังป้องกันคิว/ทรัพยากร แต่ไม่ถูกแสดงเป็นโควตาของผู้ให้บริการ เมื่อรอไม่สำเร็จจะแจ้งว่างานยังประมวลผลไม่ได้ โดยไม่มีตัวเลขนับถอยหลังปลอม เฉพาะHTTP429จริงจึงแจ้งว่า AI ติดโควตาผู้ให้บริการ การตั้งวงเงิน/ราคาเองในหน้าควบคุมยังเป็นค่าที่แอดมินกำหนด ไม่ใช่โควตาจาก API

แหล่งอ้างอิง: [Groq rate limits และความหมายของ headers](https://console.groq.com/docs/rate-limits)

## ขอบเขตและกู้คืน

ผู้ใช้ยกเลิก **ค้นความจำตามความหมาย** แล้ว ไม่มี semantic/vector search, โมเดล embedding, ดัชนี หรือคำสั่ง /memory search ในงานนี้ ค้นประวัติเดิมยังทำงานเหมือนเดิม ไม่เพิ่มรูป/เสียง บริการ Docker หรือ dependencies

SQLiteยัง schema2 เพิ่มตารางfeedbackแบบเข้ากันได้ รุ่นเก่าไม่อ่านตารางใหม่ แต่การลบanswersยัง cascade ได้เมื่อเปิด foreign keys เก็บ backup และ imageก่อนอัปเดต พร้อม **privacy-ledger.sqlite3 ฉบับปัจจุบัน** หากย้อนกลับ อย่าทับ ledgerด้วยสำเนาเก่า การลงทะเบียนคำสั่ง/ทดสอบsyntheticไม่เท่ากับยืนยันว่าผู้ใช้กดปุ่มจริงแล้ว
