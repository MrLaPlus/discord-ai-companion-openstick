# RSS, YouTube, Playwright, โหมดเรื้อน และห้องที่คุยได้

2026-10-28 · สถานะเปิดใช้จริง/ผลทดสอบล่าสุดดู PROGRESS.md

## สามเครื่องมือที่เลือก

- **RSS ข่าว**: “RSS ข่าวล่าสุด” อ่านรายการจาก BBC Technology และ Ars Technica เริ่มต้น หรือส่ง URL RSS/Atom เช่น “อ่าน https://example.com/feed.xml” แสดงวันที่จากรายการจริง ใช้ /ask ได้เหมือนเดิม ข่าวทั่วไปลอง feed ก่อน ถ้าไม่พบหรืออ่านไม่ได้จึงค้น DuckDuckGo ภายในงบไม่เกิน2 MCP calls ต่อคำถาม เมื่อระบุ RSS ชัดเจนจะไม่แอบอ้างผลค้นเว็บว่าเป็น RSS
- **YouTube Transcript**: “สรุป https://youtu.be/…” ดึงซับสาธารณะไทย/อังกฤษพร้อมเวลา ไม่ต้องมี API key เพิ่ม เป็นตัวอย่างซับไม่เกิน5ช่วง ไม่ได้ดูภาพหรือฟังเสียง และไม่อ้างว่าอ่านครบคลิป หากไม่มีซับ/ถูกจำกัด/DNS ขัดข้องต้องแจ้งว่าอ่านไม่ได้ ไม่แต่งสรุป
- **Playwright MCP**: “ใช้ Playwright อ่าน https://…” รัน JavaScript แล้วอ่าน DOM เป็นข้อความ หรือเป็น fallback หนึ่งครั้งเมื่อการอ่านเว็บธรรมดาล้มเหลว ไม่มีคำสั่งกดปุ่ม กรอกฟอร์ม login รันโค้ดตาม AI หรือดาวน์โหลดไฟล์ บางเว็บใช้ POST/API หรือบล็อก automation จึงอาจอ่านได้ไม่ครบ

Playwright รุ่นนี้เป็น **MCP reader ที่เขียนจำกัดขอบเขตด้วย Microsoft Playwright Python1.64.1** ไม่ใช่การเปิดชุดเครื่องมือ automation ทั้งหมดของ microsoft/playwright-mcp ใช้ MCP SDK2.3.0 ร่วมกับระบบเดิม ตัว RSS ใช้ defusedxml0.7.1 และ captions ใช้ youtube-transcript-api1.2.4 (keyless) ทั้งหมดล็อกเวอร์ชัน/hash

ยังซ่อนที่มาจนถาม “เอามาจากไหน” และแบ่งข้อความยาวเหมือนเดิม ไม่เพิ่ม Discord admin/write MCP, ภาพหน้าจอเข้า หรือเสียง voice ในงานนี้

## โหมด4 “เรื้อน”

เลือก `/tone level:4` สำหรับตัวเอง แอดมินตั้งเพดานห้องด้วย `/settings tone level:4` ค่าใช้จริงยังเป็น **ค่าที่ต่ำกว่าระหว่างคนกับห้อง** ระดับ0หยุดแซว ระดับ1–3ใช้บุคลิกเดิม ระดับ4เพิ่มมุกเปรียบเทียบเพี้ยน ๆ โวยวายเว่อร์แบบขำ แซวสถานการณ์/แซวตัวเอง และ punchline สั้น ๆ ไม่ใช่เพิ่มความหยาบอย่างเดียว

ตัวอย่างทิศทาง: “แพ้ติดสามตานี่เกมมันไม่ได้จับคู่แล้ว มันจับมึงบูชายัญให้ทีมตรงข้าม 555” เป็นตัวอย่างออกแบบ ไม่ใช่ผลสุ่มจากโมเดลที่รับรองว่าจะออกเหมือนกันทุกครั้ง

ยังหยาบได้เล็กน้อยตามความยินยอม ไม่ด่าคุณค่าของคน ไม่ไล่ผู้ใช้เมื่อถามความสามารถ ไม่กวนเรื่องความทุกข์จริงจัง และไม่แต่งข้อเท็จจริง/สกอร์เพื่อทำมุก คำตอบข้อมูลให้สาระก่อนมุกได้ไม่เกินหนึ่งประโยค ตัวกัน trace/คำด่าที่พบเดิมยังทำงาน

## ห้องไหนคุยได้

เปิด `AUTO_RESPOND_ACCESSIBLE_CHANNELS=true` ใน .env แล้วห้องข้อความในเซิร์ฟเวอร์ที่กำหนดซึ่งบอทเห็นและส่งได้ เรียกด้วยแท็ก/ตอบกลับได้โดยไม่ต้องเปิด respond ทีละห้อง ห้องบอทเดิมยังคุยโดยไม่แท็ก; การแทรกคุยยังไม่เปิดเอง

ห้องใหม่ที่ไม่เคยตั้งค่า **ไม่เปิดเก็บประวัติ/แชร์ข้ามห้องเอง** ใช้ความต่อเนื่อง RAM ตามคน/ห้อง/โหมดส่วนตัวได้ และหมดอายุตามเดิม เพดานโทนห้องใหม่รองรับ4 แต่ค่าคนเริ่ม1จึงไม่ทำให้ทุกคนถูกแซวแรงทันที

ค่าปิดตอบรายห้อง/พักรายห้องหรือทั้งเซิร์ฟเวอร์ยังมีผล ปิดด้วย `/settings channel ... respond_here:false` หรือ `/pause` และปิดเครื่องมือแยกด้วย `/mcp channel mode:off` ได้ ห้องที่ยังไม่กำหนดโหมดเครื่องมือใช้ hybrid เมื่อเปิด auto-response ส่วนค่า off ที่แอดมินกำหนดไว้ยังคงอยู่

ก่อนทำงาน/ส่งแต่ละส่วนตรวจสิทธิ์ Discord ใหม่ ถ้าไม่มี ReadMessageHistory จะไม่ดึงแชทย้อนหลังหรือ REST-fetch ข้อความเก่า ใช้ข้อความใหม่จาก Gateway ภายใน30วินาทีและส่งคำตอบปกติ ปุ่มที่ต้องตรวจต้นทางย้อนหลังจะไม่แสดง; ใช้ /ask เพื่อถามส่วนตัวได้

## Docker และเครือข่าย

สี่ service ไม่มี GUI และไม่เปิด host ports:

| Service | หน้าที่ | สิทธิ์/เครือข่าย |
|---|---|---|
| bot | Discord/Groq/คิว/ACL/โทน | เก็บคีย์และ volume เดิม ไม่ส่งคีย์ให้ service อื่น |
| mcp-web | ค้นเว็บ/RSS/ซับ/ตัวเชื่อม browser | ไม่ได้คีย์บอทหรือฐานข้อมูล; อ่าน feed ผ่าน HTTPS IP pinning |
| mcp-browser | MCP read_page + Chromium | root read-only, UID10003, ไม่มี volume/credentials, internal network เท่านั้น, context ใหม่ต่อการอ่าน |
| web-proxy | HTTPS CONNECT443 | ตรวจ DNSทุกคำตอบและเชื่อม literal IP ที่ผ่าน public-address check จริง; ไม่รับ HTTPทั่วไป |

เบราว์เซอร์บังคับ proxy รวม loopback, ปิด QUIC/non-proxied WebRTC, service workers และ WebSockets กรอง request ให้เป็น GET HTTPS; TLS certificate ยังตรวจชื่อจริง ไม่ใช้ ignore-https-errors ตัว proxy ไม่ได้เปิดสิทธิ์ให้เว็บเข้าหา localhost/private/metadata resource

Chromium ใช้ --no-sandbox เพื่อรันใน container ที่ไม่ให้ privilege เพิ่ม จึงใช้การแยก container/network/ตัวกรอง request ร่วมกัน ไม่ใช่คำรับรองว่ารันโค้ดเว็บใด ๆ ได้โดยไม่มีความเสี่ยง กำหนด browser768MB/CPU1/pids256/tmp128MB/shm128MB; proxy128MB/CPU0.5/pids64 ข้อมูล/browser profile ทิ้งหลังอ่าน

เปลี่ยนแหล่ง RSS ผ่าน `RSS_FEEDS` เป็น JSON array ของ1–3 public URLs เฉพาะตัวแปรนี้ถูกส่งให้ mcp-web ไม่ส่ง .env ทั้งชุด เครื่องมือเพิ่มจาก2เป็น6 ชื่อและ schema ยังตรวจแบบ fail-closed เปลี่ยน schema pin ได้เมื่อ operator ตรวจรุ่นใหม่เท่านั้น

งบเดิม6 MCP calls/นาที,100/วัน/instance,10/วัน/คนและโควตา AIร่วมกันยังอยู่ คำถามละไม่เกิน2calls; browserจำกัด30วินาทีที่ client และมี deadlineภายใน20วินาที งานรวม90วินาที DNS4วินาที/feed8วินาที คำขอผิดพลาดไม่ทำให้คิวค้าง
